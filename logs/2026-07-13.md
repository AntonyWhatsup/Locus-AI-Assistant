 # Settings Module Refactor Plan                                                             
                                                                                              
  ## Summary                                                                                  
                                                                                              
  Refactor the current settings implementation into a maintainable settings domain that       
  still preserves existing runtime behavior. The new design keeps data/settings.json as the   
  persisted source, supports only the current five user settings, and retains config globals  
  as a compatibility layer so the rest of the app does not need a broad rewrite in v1.        
                                                                                              
  ## Key Changes                                                                              
                                                                                              
  - Introduce a typed settings model as the single schema/defaults/validation source for:     
      - language_code
      - wake_words                                                                            
      - gemini_model                                                                          
      - theme                                                                                 
      - animation_speed                                                                       
                                                                                              
  - Replace scattered settings logic with a dedicated settings service in the current         
    settings area:                                                                            
      - load persisted JSON                                                                   
      - merge with defaults                                                                   
      - validate and normalize values                                                         
      - save validated settings                                                               
      - apply settings to runtime compatibility globals in config                             
                                                                                              
  - Move settings-related enums and option metadata out of UI-only code so the domain owns    
    allowed values and labels, while the Tkinter window consumes that metadata instead of     
    redefining it.                                                                            
                                                                                              
  - Keep config.py as a compatibility boundary for runtime consumers like processor.py,       
    actions.py, and startup code:                                                             
      - defaults remain available there if needed by non-settings code                        
      - mutable runtime globals are updated only through the settings service                 
      - direct schema knowledge should stop living in config                                  
                                                                                              
  - Restructure the settings window in /D:/GitFile/Locus_AI_Assistant/src/ui_manager.py to    
    work with a draft settings object:                                                        
      - populate the form from the typed model
      - validate fields before save                                                           
      - show inline field-level errors instead of silently falling back                       
      - apply all changes only on Save                                                        
      - keep Cancel as no-op                                                                  
                                                                                              
  - Preserve current side effects after successful save:                                      
      - sync runtime config globals                                                           
      - reload Gemini client when model-related settings are applied                          
      - refresh theme-dependent UI state                                                      
      - refresh wake-word display and animation timing                                        
                                                                                              
  ## Public Interfaces / Types                                                                
                                                                                              
  - Add a typed Settings value object or dataclass as the canonical in-memory                 
    representation.                                                                           
                                                                                              
  - Add a SettingsService-style API with explicit responsibilities such as:                   
      - load() -> Settings                                                                    
      - validate(raw_input) -> validated settings + field errors                              
      - save(settings)                                                                        
      - apply(settings)                                                                       
                                                                                              
  - If needed for UI binding, add a lightweight form payload type separate from the           
    persisted/runtime model so raw entry strings do not leak into the core settings object.   
                                                                                              
  - Keep a compatibility function layer around the old entrypoints if other modules already   
    import them, but have those functions delegate to the new service.                        
                                                                                              
  ## Test Plan                                                                                
                                                                                              
  - Unit tests for the typed model/service:                                                   
      - defaults are produced correctly                                                       
      - wake words normalize from string and list input                                       
      - invalid enum values are rejected in validation                                        
      - blank required strings produce validation errors instead of silent overwrite in UI    
        flow                                                                                  
                                                                                              
      - JSON load handles missing file and invalid JSON safely                                
      - save writes the validated canonical JSON shape                                        
      - apply updates all runtime compatibility globals correctly                             
                                                                                              
  - UI-oriented tests at the behavior level where practical:                                  
      - settings form loads current persisted values                                          
      - cancel closes without mutating persisted settings

      - theme and animation updates still affect the dashboard after save

  ## Assumptions

  - v1 keeps data/settings.json with no schema versioning or migration system.
  - v1 covers only the existing five settings; no microphone/device/personality settings are  
    added yet.


  - Save-time application remains the UX model; there is no live preview beyond what already  
    happens after a successful save.

  - Inline validation errors are limited to the settings window and do not require a broader  
    notification system.
